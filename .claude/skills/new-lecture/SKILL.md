# /new-lecture — master prompt first, then SDLC sync, then one review

Input: lecture title + transcript (ask and stop if missing). Flags on the first line, all optional: `--strict`, `--no-sdlc`, `--review`, `--no-review`, `--commit`, `--push`.

**The master prompt is the contract for the notes.** Read `master-prompt.md` once (skip if it is in context). This skill adds only workflow and tools; if the two ever disagree about a note's content or format, the master prompt wins. Everything in master prompt §§4–9 applies, in particular:
- **File names and folders (§4):** `course-N-…/module-N-…/notes/NN-<topic>.md`, `images/NN-<topic>-<short-name>.svg`; lowercase letters, digits and hyphens only; Windows-safe.
- **Sections in this exact order (§6):** 1 Jargon Translation (official definition + simple words + analogy) · 2 Topics list (numbered) · 3 Exhaustive Deep Dive (one heading per concept, micro-mechanics "how and why", nested bullets and tables, bold key terms, at least one Mermaid diagram per major topic, images where they help) with **✅ Modern Best Practice blocks** (own heading; two-line "Lecture says / Industry today" quote; how it is done today with tools and the why; table, diagram or code; a `✅ Modern best practice` column in the summary table) and a gap check (**"Often-missed parts"** and a **"done enough when…" checklist**) · 4 Concrete Examples tied to course projects (REST API, Express, Docker, Kubernetes, databases) · 5 Code (JavaScript/Node.js first; minimal working example, comments on significant lines, a **"What happens if…"** variation; `bash` for Docker/Kubernetes/CLI; code only where it helps) · 6 **Exactly 5** Related Concepts · 7 Lecture summary table.
- **Extract every detail** of the transcript; **add** important industry concepts the lecture lacks and mark them clearly ("Not in the lecture — industry practice").
- **Corrections (§4):** a `⚠️ **Correction:** wrong → right` badge with a `**Lecture wording (for the quiz):** "…"` line, and the corrected version used everywhere else (text, tables, jargon, Mermaid, SVG text and captions, examples, code comments, topics list, summary). Outdated or oversimplified practice becomes a Modern Best Practice block.
- **Images (§7):** at least 2 SVGs, embedded with image syntax (caption text, then the relative path `../images/NN-<topic>-<short-name>.svg`). **Mermaid (§8):** `flowchart TD`, quote labels with special characters, no `( ) < > "` in edge labels, margin node in `direction TB` subgraphs.
- **Output rules (§9):** **no fluff and no meta-commentary** (no "how to read these notes" preface, no closing remarks); expand every acronym at first use; B1 English; the notes teach only the correct version. After the file, give the numbered **topic summary** in chat (§5 step 7).

**Soft length guide:** about 0.5 lines per transcript word; completeness first, no padding. **Efficient output:** one `Write` for the note (patch with `Edit` or a Python replace); reading a written file back is fine when a check needs it.

## Steps

1. **Prep:** `python .claude/skills/new-lecture/scripts/prep.py <slug>` (pull, module, number, folders). Save key points (~300 words) to the TRANSCRIPT path.
2. **Plan:** write `keys.txt` — **one exact phrase for every distinct statement, definition, list item, example and number in the transcript** (about one per 15–20 words; this is how "extract every detail" and master §5 step 6 "100% coverage" are checked) — and `leaks.txt` (wrong phrases you will correct). List corrections and modern-practice blocks.
3. **Verify facts:** for every number, date, version, standard or quoted wording, run `python .claude/skills/new-lecture/scripts/fetchgrep.py <primary-url> "<regex>" …` (a script; only matching snippets enter the conversation; run several in parallel; 10–15 checks is normal). Use `WebSearch`/`WebFetch` when a page fails. One retry per URL, then hedge or drop the claim.
4. **Write the note and SVGs.** Default: one `Write`, then the **final audit of master §5 step 6**: compare the whole note with the transcript for missing details, redo the correction sweep, check every fact you added. **With `--strict`:** follow master §5 literally: write one major section at a time, compare it with the transcript right away, refactor, do the correction sweep, then continue; then the final audit. Run code for technical lectures (no external service) and paste real output.
5. **Check the note (fix, rerun once):**
   `python .claude/skills/new-lecture/scripts/audit.py <note> <svgs> --keys keys.txt --note <note> --leak-file leaks.txt --acronyms` (also checks master §8 Mermaid rules, links, SVG validity, file names, badge/quiz-line count)
   `python .claude/skills/new-lecture/scripts/riskcheck.py <note>` — each `??` line becomes **verified** (add the source), **hedged** or **removed**; target 0 unmarked. Also confirm by eye: no meta-commentary preface, exactly 5 related concepts, a summary table with the ✅ column, an "Often-missed parts" section with a "done enough when…" checklist.
6. **SDLC sync (automatic; skip only with `--no-sdlc`):**
   1. `python .claude/skills/new-lecture/scripts/gaps.py "pattern|alt" …` — one pattern per practice from the note's Modern Best Practice blocks, corrections and checklist (`<- GAP` = add; hits = extend or link; never duplicate); one grep for the corrected wrong phrases over `SDLC/`.
   2. Edit real gaps only: at most one new subsection per affected phase file; append rules **after the current last number of that list** (`grep -n "^[0-9]*\. \*\*" file`; never renumber); must/should/may with an owner and tailoring by project type; at most one template (register it in the phase table and README §8); README §10 row only for a new standard; update "Last reviewed/Next review due" only in changed files; link the course note.
   3. Re-verify the 5 riskiest new SDLC facts with `fetchgrep.py`. Add a CHANGELOG entry (about 10 lines). Run `python .claude/skills/new-lecture/scripts/audit.py SDLC --rules` → 0 problems.
7. **One independent review** of the note **and** the SDLC change. Runs when the SDLC step ran, or with `--review`, or when riskcheck says `REVIEW RECOMMENDED`, or with 3+ corrections; skip only with `--no-review`. One subagent, `model: "sonnet"`, no web. Give it the note, the transcript, `master-prompt.md`, `git diff` for `SDLC/`, and the audit and riskcheck output. Ask: (a) transcript points missing or distorted; (b) master prompt rules broken (section order, badge format, B1 English, exactly 5 related concepts, ✅ column, meta-commentary); (c) wrong, outdated or invented claims and claims without source or hedge; (d) SDLC rules that contradict existing rules, lack an owner or default, or are impractical for 4–8 people; (e) beginner confusion. At most 20 findings with line numbers. **Verify each finding yourself** before applying; rerun the audits.
8. **Finish.** Give the numbered topic summary and a report of about 15 lines: corrections, what was verified, what was hedged or not verified, SDLC rules and templates added, audit and riskcheck results, whether the review ran. Never commit `HANDOFF.md`. Commit only with `--commit`/`--push`, as two commits (`notes: add NN <Title>`, `SDLC: add note-NN <topic> practices`); push only with `--push`. Otherwise ask once: "commit and push?"
