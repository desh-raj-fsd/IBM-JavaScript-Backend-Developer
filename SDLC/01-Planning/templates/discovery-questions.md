# Discovery Questions — <Client name> / <Project idea>

> Use in the **first discovery meeting**. Owner: Product Owner. Copy to `docs/discovery/discovery-questions.md` and write the answers here.
> **Tips:** ask open questions ("tell me about…"), keep asking **"why?"**, and ask for **real examples**. Do not talk about technology unless the client asks. Record the meeting only **with the client's permission**.

## Before the meeting (our team)
- [ ] Read the client's short brief and website; list what is unclear
- [ ] Look at 2–3 competitor or similar apps
- [ ] Decide who asks questions (PO) and who takes notes (DL or TL)
- [ ] Ask the client: "Who will make the final decisions? Please bring them."

## 1. The problem
| Question | Answer |
|----------|--------|
| What problem are you trying to solve? | |
| What happens today without this product? (tools, paper, Excel, another app?) | |
| What is the cost of this problem today? (time, money, lost customers) | |
| Why do you want to solve it **now**? | |

## 2. Users
| Question | Answer |
|----------|--------|
| Who will use it? Describe **one real person** (job, age, skills, device). | |
| Are there different types of users? (customers, staff, admins) | |
| How many users at the start? In one year? | |
| Where and on what device will they use it? (phone, desktop, in the field, slow internet?) | |

## 3. Success
| Question | Answer |
|----------|--------|
| In 6 months, how will you know this was worth the money? | |
| Which number should go up or down? (sales, sign-ups, hours saved) | |
| What would make this project a **failure** for you? | |

## 4. Features and examples
| Question | Answer |
|----------|--------|
| Walk me through what a user does, step by step, from start to finish. | |
| Show me 2–3 apps or websites you like. What exactly do you like? | |
| If we could build only **3 things** first, which 3? | |
| What is "nice to have" but can wait? | |
| Is there anything you definitely do **not** want? | |

## 5. Data and other systems
| Question | Answer |
|----------|--------|
| What information do users enter? What do they get back? | |
| Do we store personal data? (names, emails, payments, health, children's data) | |
| Must it connect to other systems? (payments, email, CRM, accounting, maps, login with Google) | |
| Do you have existing data we must move (migrate)? | |

## 6. Limits
| Question | Answer |
|----------|--------|
| What is your budget range? | |
| Is there a fixed date? Why that date? (event, investor, law) | |
| Rules or laws that apply? (privacy, accessibility, industry rules) | |
| Who makes the final decisions? Who else must agree? | |
| Who will run and pay for the system after launch? (hosting, support) | |

## 7. Red flags to note (do not ask — observe)
- [ ] No clear decision-maker
- [ ] "Everything is a must-have"
- [ ] Fixed date and fixed budget **and** a large, unclear scope
- [ ] Sensitive data (payments, health) but no one owns compliance
- [ ] Client wants to start coding **before** agreeing on the scope

## After the meeting

- [ ] Add new assumptions and decisions to the [assumptions and decisions log](assumptions-and-decisions-log.md)
