# MVP Workshop — <Project name> — <date>

> Run this **after** the client has clicked through the prototype. Owner: Product Owner (facilitator); Tech Lead gives size estimates. Duration: 1.5–2 h.
> Copy the result to `docs/discovery/mvp-workshop-<date>.md`. The final feature list goes into the [client PRD](client-prd.md).

## Goal
Agree on the **smallest first version (MVP — Minimum Viable Product)** that solves the main problem and can go live. Everything else goes into **phase 2 or later**.

## Agenda
| Time | Step |
|------|------|
| 10 min | Remind everyone of the **problem** and **success metric** (from the meeting summary) |
| 20 min | Walk through the prototype; list **every** feature mentioned (one per sticky note / row) |
| 30 min | Sort each feature with **MoSCoW** (rules below) |
| 20 min | Check the "Must" list against the **budget and date** (TL gives T-shirt sizes) |
| 15 min | Cut or move features until the Must list fits |
| 10 min | Read the final list aloud; confirm decisions; agree next steps |

## MoSCoW rules
- **Must have** — without it, the product **cannot go live** or does not solve the main problem. Test: *"Would you launch without it?"* If yes → it is not a Must.
- **Should have** — important, but there is a workaround for now.
- **Could have** — nice extra; only if there is time.
- **Won't have (this time)** — agreed **not** to build in this version. Writing this down is as important as the Must list.
- **Rule of thumb:** Must haves should be **no more than about 60%** of the effort, so there is room for surprises.
